## Architecture / proposed approach

**形式契约 = `html-brochure-pdf`**：手工设计级 HTML（A4 竖版，210×297mm，inline CSS）→ Playwright Chromium 渲染 PDF。设计基调沿用该 skill 的工业质量调性：**深藏青主色 #0B1E30 + 科技蓝强调 #1F5FE0（AI 专属）+ 白底细网格**；语义色（绿 #189A5B/橙 #D9820B/红 #D64545）只用于风险/状态分级；全 inline SVG 线条图标、零 emoji、无渐变彩色条、无左边框彩色 KPI 卡（YOO 去 AI 味偏好）。

**工作流 = `content-production-pipeline` 五阶段**，任务分配按 delegation-optimization-strategy（环境重型→主进程，纯逻辑生成→子代理，渲染→主进程）：

| 角色 | 执行者 | 内容 |
|------|--------|------|
| 阶段1 叙事架构+文案 | **子代理 A** | 12 页大纲 YAML + 每页文案（含去AI味12条自检） |
| 阶段2 人工终审 | **YOO** | 审大纲+文案，锁定 |
| 阶段2.5 工程初始化 | 主进程（孔明） | 目录骨架、assets 拷贝、design token 模板 |
| 阶段3 页面 HTML | 主进程（孔明） | 封面锚定页 → 分 3 批生成 12 页 builder |
| 阶段4 质检修复 | **子代理 B** + 主进程 | 合规/去AI味/版式 QA 报告 → 主进程修复（≤2轮） |
| 阶段5 渲染校验交付 | 主进程（孔明） | Playwright PDF + geometry QA + fitz 终验 + 交付 |

## Risks, tradeoffs, and open questions

### Risks
1. **mock 口径漂移**：9/7 mock 早于 SPC 6 控制图（9/15 提交）等更新，画面与文案可能矛盾 → Task 7 强制核对，重绘有现成 recipe（ui-mockups.md），成本可控
2. **vision 504**：大图走 frp 超时 → 一律先缩 640px jpg 再送；vision 判断不可靠时以 geometry 脚本为准（skill 已沉淀）
3. **A4 竖版留白两大病因**：头重脚轻/对称白带 + 卡片撑高后内部空洞 → 任务 6/7 的 builder 规则已内化 skill 结论（flex 撑满 + 横卡拓扑），QA 双通道兜底
4. **子代理文案质量波动**：Task 2 主进程抽验 3 页 + 门禁不过退回（≤2 轮）；极端情况文案改主进程写（素材已核实，主进程写 12 页文案工作量可控）
5. **PDF 超 20MB**：当前素材量预估 3–6MB，低风险；若重绘 mock 增多导致超限 → 图片压缩到 150DPI

### Tradeoffs
- **只做电子 PDF，不做印刷版**：省掉 CMYK/出血/打样环节；如 YOO 后续要印刷版，HTML 源可复用，另加转换步骤
- **主进程写 HTML 而非子代理**：12 页手写 HTML 是风格敏感工作，子代理风格漂移风险 > 主进程 context 开销；且 html-brochure-pdf 的全部坑都在主进程 skill 里
- **复用 9/7 mock 而非全部重绘**：省 2-3 小时；代价是画面细节未必匹配最新版本，靠 Task 7 核对兜底
